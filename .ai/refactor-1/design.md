### Dependency Direction (STRICT — no violations allowed)

```
driver  --->  controller  --->  adapter  --->  types
  |               |                              ^
  |               +-------->  util  <------------+
  +---------------------------------------------->
```

Rules:
1. **driver** imports controller + types + util. NEVER imports adapter directly.
2. **controller** imports adapter + types + util. NEVER imports driver.
3. **adapter** imports types + util. NEVER imports controller or driver.
4. **types** imports NOTHING from internal.
5. **util** imports types. NEVER imports adapter, controller, or driver.

```go
    HomeURL   string

// driver/http/portfolios.go
func (h *Handler) HandlePortfolios(...) {

    // ... 60 lines of enrichment, sorting, stat computation

```

### AFTER: Handler delegates to controller services
```go
// driver/http/handler.go
type Handler struct {
    BaseDir          string
    Templates        map[string]*template.Template
    HomeURL          string
    PortfolioService controller.PortfolioService
    WorkspaceService controller.WorkspaceService
    ForgeService     controller.ForgeService
}

// driver/http/portfolios.go
func (h *Handler) HandlePortfolios(w http.ResponseWriter, r *http.Request) {
    sortMode := r.URL.Query().Get("sort")
    data, err := h.PortfolioService.ListPortfolios(h.BaseDir, sortMode)
    if err != nil { ... }
    data.DarkMode = isDarkMode(r)
    data.HomeURL = h.HomeURL
    h.render(w, "portfolios", data)
}
```

The business logic (enrichment, sorting, stat computation, heatmap building) moves to `controller/portfolio.go`, `controller/workspace.go`, and `controller/forge.go`.

## 8. Critical Design Notes

### 8.1 Dual Template Systems (NOT unified)
The project has TWO independent rendering paths:
- **WASM path**: `controller.PageRenderer` + `//go:embed templates/*.html` -> returns HTML string
- **HTTP path**: `driver/http` uses `template.ParseFiles` (filesystem) -> renders via `h.render(w, name, data)`

The new controller services (`PortfolioService`, `WorkspaceService`, `ForgeService`) return **data only** (types.XxxPageData structs). They do NOT render templates. Template rendering remains in `driver/http` (filesystem templates) and `controller/renderer.go` (embedded templates for WASM).

This is intentional: the controller services encapsulate business logic (enrichment, sorting, stat computation), while template rendering is a driver concern.

### 8.2 Portfolio-Workspace Intra-Package Dependency
After merging portfolio/ and workspace/ into adapter/:
- `portfolioDiscovery.List()` calls `workspaceDiscovery.List()` internally
- Both are now in `package adapter`, so this becomes an intra-package call
- The `portfolioDiscovery` struct can hold a reference to the `workspaceDiscovery` impl directly
- Alternative: `portfolioDiscovery` takes a `WorkspaceDiscovery` interface (better for testing)
- Decision: **Use interface injection** — `NewPortfolioDiscovery(ws WorkspaceDiscovery) PortfolioDiscovery`

### 8.3 enrichWorkspaces Migration
The `enrichWorkspaces` function currently takes concrete `*cache.Cache`. After migration to controller:
- Signature changes to use `adapter.Cache` interface
- All forge.Load() calls change to use `adapter.ForgeLoader` interface
- This is what enables mock-based testing of the enrichment logic

### 8.4 WASM Path Unchanged
`cmd/forge-ui-wasm/main.go` uses `adapter.NewDemoDataSource()` + `controller.NewPageRenderer()`. These are untouched. The WASM path is fully decoupled and unaffected by this refactoring.

## 10. Risks and Mitigations

| Risk | Severity | Mitigation |
|------|----------|------------|
| Large adapter/ package with many files | MEDIUM | Each file is self-contained with interface+impl+constructor. Clear naming. |
| Test function name collisions after merge | LOW | Verified: no collisions between portfolio_test.go and workspace_test.go |
| forge go-gen-mocks may not auto-discover all interfaces | MEDIUM | Fallback: write mocks manually following mockery pattern |
| driver/http tests need filesystem templates | MEDIUM | Use test fixtures with minimal templates |
| Refresher tests become slower with real I/O | LOW | Keep existing filesystem tests, add mock-based tests alongside |
| Portfolio impl needs workspace impl (circular?) | LOW | Use interface injection: NewPortfolioDiscovery(ws WorkspaceDiscovery) |
